AI agent & LLM security testing

Understand what your agent can access, what it can do, and whether untrusted input can push it past those boundaries. Independent manual testing for startups moving AI products into customers’ hands.

Test the application around the model.

An assistant can produce a convincing answer while its retrieval layer exposes another customer’s files or its tools act with too much authority. The review follows input from the user and retrieved content through to the data and actions it can reach.

We agree the application, roles, data sources and workflows in scope first. Testing focuses on reproducible application impact, with the context your engineers need to fix it.

What an AI security review can cover

Prompt injection

Direct messages and indirect input from documents or tool responses. Check whether manipulated instructions reach private data or privileged actions.

RAG and private retrieval

Whether the retrieval pipeline applies the caller’s permissions before private context reaches the model, including separation between customers and roles.

Agent tools and MCP integrations

Which tools the agent can call, how arguments are checked, and where identity and authorization are enforced around connected services.

Output, credentials and data flow

How responses, browser storage, logs and downstream integrations handle sensitive data. Check the paths beyond the chat window as well as the answer itself.

From a finding to a fix your team can use

  1. Agree the scope. Identify the agent’s role, integrations, test users and expected permissions.
  2. Exercise real workflows. Investigate the access and action boundaries with controlled test data.
  3. Report confirmed impact. Document evidence, reproduction steps, severity, limitations and recommended fixes.
  4. Check the agreed fixes. One retest is included in the one-time review.
